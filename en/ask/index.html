Ask a question about the published schedules in plain words. An AI model writes one database query; your browser runs it on Roshni's published data, so every number in the answer comes from that query. The model only writes the words around the numbers, and its sentences are checked before you see them.

How an answer is made

Seven stages, three of them language models. Every model output is checked by code before it reaches you.

  1. 1

    Route the question

    A deterministic router in your browser sends questions about your own supply to the site's schedule engine, the same TypeScript as My feeder, tested case for case against the Python pipeline. No model is called and no question is used up.

    • ifIntent router
    • ⏱Schedule engine
  2. 2

    Admit it

    The Cloudflare Worker enforces per-visitor limits (10 a day, 3 a minute), a site-wide limit and a daily token budget, all held in a Durable Object. Usage is counted without keeping question text.

    • Cloudflare Workers
    • Durable Objects
  3. 3

    Screen for injection

    Meta's Llama Prompt Guard 2 (86M parameters), served by Groq, classifies the question and returns the probability that it is a jailbreak or injection. A score of 0.5 or more is blocked before any SQL is written.

    • Llama Prompt Guard 2
    • gqGroq
  4. 4

    Text to SQL

    Qwen3.8 27B on Groq writes one query at temperature 0 in JSON mode, seeing only the semantic layer: 10 published tables with every column described. If a model is busy the chain falls back to gpt-oss-120b, gpt-oss-20b, then free models on OpenRouter. It may refuse instead, with a reason.

    • Qwen3.8 27B
    • gptgpt-oss-120b
    • gptgpt-oss-20b
    • OpenRouter
  5. 5

    Check the SQL

    DuckDB's own parser turns the query into a parse tree (json_serialize_sql). The guard walks it and allows only a SELECT on semantic-layer tables and columns: no table functions, no blocked functions, no SELECT *. The Python twin uses sqlglot, and a shared fixture keeps both verdicts identical.

    • DuckDB
    • sgsqlglot
  6. 6

    Run it in your browser

    DuckDB-WASM, self-hosted and pinned by hash, runs the query on the site's published Parquet and JSON, with a 10-second limit. An error, an empty result or a guard refusal earns one corrected try, with the reason sent back to the model.

    • DuckDB-WASM
    • WebAssembly
    • Parquet
    • JSON
  7. 7

    Grounded narration

    The model sees the column names and the result's facts and writes one to three sentences that point at them with placeholders; your browser fills in the values. A checker rejects stray digits or number words, causal words and wording that turns a schedule into a measured outage, and a plain template is shown instead.

    • Qwen3.8 27B
    • ✓Prose check
